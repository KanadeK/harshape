# Design and acceptance

User: a support engineer or developer who needs a timing waterfall without disclosing raw URLs/payloads. Complete workflow: export a stable HAR → produce a new reduced file locally → inspect the generated counts and projection → share it through the user's chosen channel. The CLI never transmits a file.

The input loader enforces a pre-parse byte bound, regular-file input and strict duplicate-key/constant handling. A projection builds fresh dictionaries from a small fixed output schema. No arbitrary source dictionary, array, key or string is copied. Standard method/protocol/MIME enums and finite numeric performance fields are exceptions intentionally retained. HMAC-SHA256 maps origins and contextual path prefixes to 128-bit tokens using one ephemeral 256-bit key. Query/userinfo/fragment values are excluded from HTTP(S) grouping. Other absolute URL schemes are opaque. Time offsets are measured from the earliest entry, then anchored to a fixed epoch. New output files are created exclusively.

Required acceptance: remove canaries from all standard free-text locations and unknown extensions; preserve numeric performance fields, same-endpoint grouping and relative time offsets; distinguish origins/ports and contextual segments; generate different pseudonyms on a new run; handle empty captures, data/file/blob URLs, UTF-8 BOM, invalid JSON, NaN/Infinity, duplicate keys, bounds and malformed timestamps; never mutate input or clobber existing output. Exercise actual file/CLI flow and a fresh installed-wheel demo. Record structural HAR schema validation separately from browser import testing, and do not claim anonymity.

Research reviewed on 2026-10-23: [Cloudflare issue #44](https://github.com/cloudflare/har-sanitizer/issues/44) demonstrates the limits of particular selective-regex coverage; [Supabase #51638](https://github.com/supabase/supabase/issues/51638) illustrates real support workflows requesting cleaned captures. [Cloudflare har-sanitizer](https://github.com/cloudflare/har-sanitizer) and [ErikApption/har-anonymizer](https://github.com/ErikApption/har-anonymizer) are alternatives when retaining more debugging information is necessary. The [HAR 1.2 reference](https://github.com/ahmadnassri/har-spec/blob/master/versions/1.2.md) defines structure. The abandoned W3C draft is not treated as a current standard. No third-party implementation is copied.

Residual disclosure: lengths, timing, volume, known enums and graph structure; no statistical-anonymity, malicious-input encoding detection in numeric channels, cross-file mapping, request replay, browser import guarantee, live snapshot or filesystem sandbox. Bounded input/output counts do not establish bounded total RSS. The user's updated Python runtime supplies JSON parsing and cryptographic primitives.
